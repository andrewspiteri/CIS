## Acceptance and evidence

Use the supplied request's nine acceptance areas: canonical ownership; at least one
real RM-08 criterion reaching implementation, an applicable check and current actual
result; freshness including additions/deletions; conservative unknown-dependency
selection; unchanged second verification with zero extra native launches; explained
material invalidation without unrelated-document reruns; bounded task output;
retained record compatibility; and actual installed-route identity and execution.

Retain one compact verification record linking ordinary native reports and local
installation manifests. Compare complete delivered bytes and inclusive operation
times, label reused versus executed work, and leave model-token savings unmeasured.
No unavailable platform or unresolved mapping is represented as verified.
